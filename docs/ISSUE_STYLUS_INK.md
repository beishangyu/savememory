# 手写笔在部分平板上墨迹表现异常（全局手写）

## 环境

- 设备：华为平板（HarmonyOS / Android 13，Chrome 116 内核）
- 视口：1174×688，DPR 1.875
- 应用：本地优先的记忆训练 PWA（Vite + React + ts-fsrs）
- 复现步骤：
  1. 打开应用 → 右下角 `✍` 打开**全局手写**
  2. 用手写笔在页面上写字
  3. 用手指滑动页面

## 现象

**笔迹画到一半会整片消失，只剩最新的一笔**，视觉上表现为「墨迹在页面滑动时乱跳」，而不是稳定停在原地。

同时在页面上放一块同样规格的 `position: fixed` 参考画布（画一条贯穿全宽的横线）——**参考线始终稳定不动**，只有笔迹在变。

## 已排除

真机采集的原始事件数据（见下）证明：

| 假设 | 结论 |
| --- | --- |
| `position: fixed` 在该设备失效 | 否 —— 画布 `getBoundingClientRect().top` 始终为 `0` |
| 浏览器取消指针导致断裂 | 否 —— 12 次落笔仅 1 次 `pointercancel`，笔画仍能画满 |
| 手指被误判成笔 | 否 —— 笔上报 `pointerType: 'pen'`，手指上报 `'touch'` |
| 画布尺寸错误 | 否 —— 采集到的尺寸与视口一致（`1174×688`） |
| 设备不支持 `pointerrawupdate` | 否 —— 支持，且笔的原始采样量远高于 `pointermove` |

## 采集到的关键数据

```
事件 ↓12 →23 ⟂44 ↑11 ✕1 ｜ 笔画 12（点 …）
canvasTops: [0]                     ← 画布从未移动
refInk.drift: 0                      ← 参考线完全稳定
overlayInk.drift: 294.4px            ← 墨迹质心跳变
scrollY at the jumps: 0              ← 跳变时页面并没有滚动
```

跳变发生在 `touchstart` 与 `pointermove` 事件上，且此时**既没有滚动、画布也没有移动**。

## 已修复的相关问题（供参照）

1. **原始采样流** —— `pointerrawupdate` 是数位板的原始采样，不受帧率合并影响。设备上笔的原始采样是 `pointermove` 的数倍，应用已改为优先使用它。
2. **不再取消任何指针事件** —— Chrome 一旦取消 `pointerdown` / `pointermove` 就停止投递该指针的原始采样，笔画会只剩两三个点。取消动作已移除，手势改由 `touch-action: none` 阻止。
3. **笔画不再随重挂载丢失** —— React `<StrictMode>` 在开发模式下会挂载→卸载→再挂载一次，放在 `useRef` 里的笔画因此被清空。现已移出 React 树（模块级注册表）。

## 尚未回答的问题

1. 墨迹质心的跳变是**真的移动了**，还是绘制顺序/测量造成的假象？
2. 若是真的移动：是 `strokes` 数组的内容或顺序被改变，还是 `redraw()` 的坐标变换有问题？
3. 需求本身需要澄清：**墨迹应该钉在屏幕上**（随手指移动而固定），还是**跟随页面内容**（像批注文档那样随内容滚动）？目前实现的是前者。

## 诊断工具

应用内置了设备诊断页，dev server 会把原始事件回传到开发机：

```
http://<局域网 IP>:5173/#diag
```

「开始采集」→ 用笔写字、用手指滑动 → 「上报数据」，数据落到 `diag/telemetry.jsonl`，
包含全部原始指针事件、每条事件时刻的画布位置与 `scrollY`、墨迹质心与像素数、设备能力、构建号。

工具栏实时显示 `↓down →move ⟂raw ↑up ✕cancel ｜ 笔画 n（点 n）｜挂载 n`。
